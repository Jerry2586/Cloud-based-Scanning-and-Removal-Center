# 本地主机网络与内核检查

本地安全代理每五分钟检查一次；授权后台安全中心显示结果、时间、范围与历史，Linux 的 appgog 安全菜单也能手工检查。网络检查只读，不修改网关、防火墙或内核参数。

## 已覆盖的固定范围

- TCP/TCP6 监听：区分回环、非回环与通配地址，报告危险端口；绑定不等于公网可达。
- UDP/UDP6：检查未连接的绑定套接字，回环与 IPv4 映射回环单独识别；非回环绑定显示警告。连接中的客户端不计为监听。格式异常或缺少任一快照显示不可用。
- 主路由：比较主机 IPv4/IPv6 主路由快照的 SHA-256，忽略流量计数，保留网关、目的地、标志、度量等配置。最多 256 条；连续两次观察不同、空清单、缺失或超出范围都显示不可用。
- 内核：只读检查 ASLR、硬链接/符号链接保护、内核指针隐藏与 dmesg 限制的五项固定参数。弱值显示警告；缺失、无法读或格式异常显示不可用。不会自动 sysctl 写入。

## 路由基线批准

首次安装不会自动接受当前路由。先通过独立可信渠道核对默认网关和路由是否合法，然后进入 appgog → 系统诊断与高级工具 → 安全中心 → 12，输入显示的完整 SHA-256 指纹。也可先执行 `appgog security-local network-fingerprint`，核验后执行 `appgog security-local approve-network <完整指纹>`。批准时再次读取路由，不一致拒绝。仅 root 可批准；命令入口验证安装目录、执行器归属与权限。

基线保存在 /var/lib/appgog-security/network-baseline.json，root:root、600。重复安装、升级与保留数据卸载均保留旧批准，不会把检测到的异常学习为合法。合法网关变化也会告警，核验后重新批准。

## 结论边界

这些快照不覆盖策略路由、所有独立网络命名空间或云安全组；运行时 nftables/iptables 规则由独立采集器检查，不证明端口实际可达。防火墙配置文件的变化另由主机文件基线检查；配置文件一致也不证明运行时规则一致。路由异常只告警，不直接断网；防止合法变更或误报中断业务与管理连接。

/proc 网络快照通过当前数字 PID 的 net 目录读取，以保留逐级拒绝符号链接的规则。每个输入最多 256 KiB。管理 API 仍限制最多 25 项、32 KiB，仅返回分类结果与证据摘要。

固定 proc 条目的再次路径查找可能刷新虚拟 inode 时间戳；读取仍严格核对打开的描述符前后状态，以及命名条目的设备、inode、类型、属主和大小。普通文件继续核对全部时间戳。路由内容仍需连续两次一致，指纹批准规则不变。

运行时防火墙另由独立只读采集器核对，菜单13、基线批准及覆盖边界见 [运行时防火墙监测](local-host-firewall-monitor.md)。
