# 本地 SSH 登录入口完整性监测

本功能随候选本地安全代理交付，复用 `host.configuration` 检测和 schema 1 主机基线。后台安全页与 Linux 管理菜单显示正常、发现变化或不可用；不输出授权文件原文、公钥、环境变量值或密码。

## 固定检查范围

从本机 `/etc/passwd` 读取 UID 0 账户，以及 shell 不属于固定禁止登录/特殊系统 shell 清单的账户。按本机记录的绝对 home 路径检查 home 与 `.ssh` 目录属主、组和权限，以及五个固定文件：`authorized_keys`、`authorized_keys2`、`authorized_principals`、`rc`、`environment`。共享 home 去重，目录或文件缺失也记录，后来新增会改变基线。全局 `/etc/ssh/sshrc` 纳入既有固定主机配置。

这是固定候选入口清单，文件实际是否用于认证或执行取决于 sshd 的生效配置。`authorized_principals` 并不是 OpenSSH 默认启用的路径；本检测只预防这个固定位置被悄然植入。参考 OpenSSH 的 sshd_config(5) 与 sshd(8) 官方手册。

## 拒绝与资源边界

Linux 上拒绝路径任一祖先或目标的符号链接、非目录祖先、非普通文件、多个硬链接，以及账户或 root 以外的文件/目录所有者、组或其他人可写的 home、`.ssh` 和目标文件。读取前后核对路径身份和元数据；扫描中账户清单或目录变化时结果不可用，不能批准为正常。

账户最多 256 条、选定 home 最多 64 个；passwd 最多 256 KiB，单个入口文件最多 64 KiB，总入口文件内容最多 1 MiB，合并主机清单最多 2048 项。不递归遍历 home，不读取私钥、shadow 或任意 `.ssh` 文件；只存摘要和有限元数据。范围超限或无法读取会显示不可用。

## 升级与合法变更

升级保留已有主机基线，不自动接受扩大的检查范围。旧基线可能出现差异，需要先核验账户、SSH 授权及目录权限，再在 Linux 菜单显式批准主机配置；命令入口为 `appgog security-local approve-host APPROVE-HOST`。在怀疑失守时不得用批准当前状态代替调查。

批准容器镜像身份前要求程序基线、主机基线和容器合同均为正常。事故解除隔离前及启动后继续检查主机配置；发现变化、警告或不可用会阻止恢复，保留原批准记录。入口文件只扫描，不自动删除密钥、改 SSH 配置、停 SSH 或中断当前管理连接。

## 尚未覆盖

不解析 NSS/LDAP/SSSD 远程身份、自定义 AuthorizedKeysFile、AuthorizedKeysCommand、AuthorizedPrincipalsFile/Command、Match、证书信任和 PAM 的全部实际认证路径；这些不能凭固定文件检查推断为安全。非选定账户、shell 启动文件、进程内存与内核威胁不在本批范围。

每五分钟周期及手工扫描是快照监测，不能保证捕获两次扫描之间的短暂改动。受同一宿主 root 控制的代理、基线和报告不能提供宿主完全失守后的独立信任证明。需要从干净环境核验和恢复，不能宣称杜绝入侵。
