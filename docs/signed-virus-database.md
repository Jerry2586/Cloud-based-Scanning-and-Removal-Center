# 玄武官方病毒库分发

该流程已通过源码提交 614acaa3bf1cb32a441892ce72d1d3b3b50a9097 的 Linux 验收：37189710268 验证 root 文件权限、传输和切换恢复边界；37189710784 下载真正官方 CVD，通过生产监测处理器与真实 mTLS 套接字传输，在本地启用后运行真正 sigtool 与 clamscan 验证正常/EICAR 样本。官方直连获取的旧证据单独保留。此次是一次性单 runner 集成验收，跨服务器、Docker 菜单整链和不同发行版仍需独立演练。

## 信任与责任

ClamAV 官方库和独立发布者分别签名。玄武只缓存已验证的库，以现有私有 CA、节点证书和节点令牌提供认证 GET；铁幕主动拉取并使用本机固定发布公钥验证清单，再用实际 sigtool 验证官方 CVD，最后实际运行 clamscan 加载新库。发布私钥不进入玄武、铁幕或正式程序包。网页只显示状态，启用由 Linux root 菜单发起。

只接受 main.cvd、daily.cvd、bytecode.cvd 三个固定文件，加 manifest.json 和 manifest.json.sig，共五个附件。不接受 CLD 差量工作文件、不执行包内脚本、不覆盖程序、基线或连接凭据。每库上限 512 MiB、合计 1 GiB；daily 必须在七天有效期内，不允许时间超前超过五分钟。相同版本但摘要或元数据变化、版本倒退、缺文件、权限过宽和软链接均拒绝。

## 独立发布环境准备

在受信任 Linux 发布机准备官方原始 CVD、匹配 release-public.pem 的 Ed25519 发布私钥和 root 专属目录。下载及刷新必须遵守官方分发服务规则，CDN 返回失败时应保留现有可用库；不能自行把 CLD 改名为 CVD。发布脚本需要 OpenSSL 和真实 sigtool。

~~~sh
sudo python3 scripts/sign-virus-db.py --input /root/official-cvd --output /root/signed-cvd --signing-key /root/publisher-private.pem
~~~

这条命令核验三份库的官方签名，生成固定的签名清单与附件。签名工具仅在源码发布环境提供，不装到玄武。把签名输出目录的五个附件通过可信通道传到玄武 root 专属目录；私钥留在发布环境。

## 玄武导入与铁幕启用

~~~sh
sudo xuanwu virus-db-import
~~~

按提示填写签名附件的绝对目录。玄武先核验发布签名、大小、哈希、官方签名和版本单调性，再切换缓存指针；失败不覆盖当前缓存。首次需要验证器时从系统软件源补装 ClamAV。

~~~sh
sudo xuanwu virus-db-status
~~~

查看缓存是否存在、当前库版本与有效期。端口开放不能代替节点身份握手。

~~~sh
sudo ironcurtain virus-db-update
~~~

铁幕须已安装病毒引擎、有完整当前库且已与玄武加密配对。该命令通过节点身份下载，验证后停止官方直连更新器、实际加载候选库、原子交换整个库目录并提交来源和版本高水位。成功后启用玄武签名库，官方计时器停用；以后的刷新继续使用这条命令或铁幕菜单 29。当前不支持自动刷新云端库或一键切回官方直连。

## 中断与异常

交换之前失败保留原库；交换之后落盘失败保留已验证的新库、旧库目录和恢复日志，下次 root 启用重试完成提交。不能把旧库回写到更高的已提交版本后面。未完成事务显示未就绪，不能被标成扫描安全。任意证据、签名或高水位损坏均需人工排查，保留日志，不自动删除可疑文件。已切换玄武来源或存在切换日志时，不恢复 freshclam 自动写库。

下载有限大小、总时限及哈希校验；TLS CA、主机名和客户端证书校验开启。库过期、玄武断开或认证失败时不会启用未验证更新。原有效库能否继续扫描由本地有效期和实际引擎结果决定。历史库目录暂保留供核查，须由管理员管理空间；此流程不等于异地灾备。

## 验证区分

常规单元测试用明确的合成头部与验证器替身检查调用顺序、故障事务、链接和权限，不能证明官方病毒库加载。独立 official-antivirus 工作流必须下载真正官方 CVD、运行真正 sigtool、走新 mTLS 分发链、启用后运行真正 clamscan 对正常样本和 EICAR 进行验证。网络和官方签名失败必须直接报失败。
