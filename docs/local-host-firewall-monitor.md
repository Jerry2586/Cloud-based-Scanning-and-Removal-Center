# 本地运行时防火墙监测

候选功能：独立 root 只读采集宿主 systemd 环境中 PID 1 所在网络命名空间的 nftables、IPv4/IPv6 iptables，以及存在时的 legacy 保存工具。它比较实际规则摘要，不修改规则、不自动关闭 SSH、不删除容器。规则数量不是防护强度或公网可达性的证明；其他网络命名空间、云厂商安全组和外部防火墙不在范围。

## Linux 菜单

运行 `appgog`，进入安全中心 → 13“运行时防火墙”。支持采集、当前完整指纹、明确批准和状态。也可运行 `appgog security-local firewall menu`。网页一键本地检查读取最近一次独立采集结果，显示未批准、变化、不可用或匹配。网页不能提交规则、指纹或命令。

批准前通过独立可信控制台核验实际规则及发布记录；然后输入完整 SHA-256。批准时再次连续采集两份，变化或摘要不匹配直接拒绝，旧基线保留。安装、升级和保留卸载不自动批准防火墙基线，原基线及证据保留。合法 Docker 网络规则变化也会告警，应复核后重新批准。

## 有界与故障

固定系统工具须 root 所有且不可被其他用户写入；发行版 alternatives 链逐级检查，并保留原工具名用于 multicall 分发。nft采用JSON及stateless输出，iptables不请求规则流量计数；仅忽略时间注释与链流量计数，保留顺序、策略、表达式、集合内容及来源。动态集合变化也可能告警。

每工具输出最多256 KiB、5秒；两份采集共30秒预算、nft最多4096顶层对象/32层/32768节点、iptables最多8192非注释行。检测到容器、无法检查部署环境、缺必要工具、命令失败、输出超限、未知格式、采集不稳定、报告超过15分钟或时间异常均不可用。匹配零规则基线仍为警告，不显示防护成功。

独立systemd服务每五分钟采集，只写受保护状态目录；限制地址族及能力，不开放监听端口。主扫描服务保持AF_UNIX。每次服务启动由固定 `ExecStartPre=+` 预检读取 PID 1 与自身网络命名空间的内核设备号/inode，仅写 root 私有身份记录，不调用外部工具、不采集规则、不接受路径或命令。此短预检需要 systemd 的完整权限；主采集进程仍受能力限制。身份记录绑定本次 systemd 启动 ID、系统启动 ID 和最多120秒单调时间窗口；缺失、旧记录、不同身份、容器环境或核验失败均不可用。普通 root 菜单直接核对 PID 1，忽略服务记录。采集器为了读取内核规则需要网络管理能力；固定程序无改写入口，但不能承诺抵御宿主root失守。不会自动安装或启动防火墙软件、改写现有业务规则；缺工具由管理员安装受信发行版软件包。

## 验证要求

解析器负面测试覆盖截断、复杂度、重复键、策略/规则/顺序/来源变化，批准竞态与坏报告保持未知。真实Linux验收须通过生产采集路径、受限systemd单元、基线保留及回滚，并仅在隔离网络命名空间中演练规则变更，不改runner或生产宿主规则。

CI 用独立网络命名空间验证实际规则、流量计数、策略与集合变化；先确认生产入口拒绝该命名空间，再仅在测试进程覆盖范围检查，以验证解析器。该测试不改宿主防火墙。容器检测依赖系统工具，不是硬件证明；宿主 root 失守时，同机证据不能建立独立信任。
