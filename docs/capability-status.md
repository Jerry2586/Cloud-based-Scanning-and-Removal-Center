### 发行载荷与宿主服务健康（v0.6.1）

v0.6.0 真实玄武安装发现正式载荷遗漏 `scripts/domain_control.py`：容器健康，但域名管理控制服务反复重启。v0.6.1 补打包输入和 Python 入口，安装在提交事务前同时验证控制服务 active 与真实 Unix `/domain` 响应；接口不可用则沿原事务回滚。升级恢复此前 inactive 的必要控制服务，证书续期定时器保留原启用偏好。

首次 local/cloud Docker 部署与同版本复用必须从六附件验签后的解包载荷执行；升级也使用签名载荷，另覆盖失效控制服务恢复及续期偏好。证书申请状态 `failed` 可由健康的控制接口报告，不能混同为服务故障，也不能宣称证书申请成功。跨主机节点对接、浏览器对自签证书的信任及 arm64/RPM 实机范围仍分别验收。

### R031 固定周期检查与维护互锁（v0.6.2）

R031 为铁幕本地主机代理增加三个固定任务：快速环境体检、已纳管目录的文件深度查杀、本地联合检测。网页只能提交已定义任务的启用状态和受限周期；不能提交路径、镜像、命令或自定义脚本。配置、任务编号、尝试次数、开始/结束时间和中断状态写入 root 私有状态文件，代理重启后恢复为可核验的 `interrupted` 或 `deferred`，不会把未完成任务显示为完成。

维护、病毒库更新和其他管理事务持有同一管理租约。租约期间周期任务延期，`dispatching` 或 `running` 时拒绝修改周期配置；任务启动失败会释放租约并保留失败证据。网页通过同源会话、CSRF 和本地角色校验访问 `/api/schedule`，Unix socket 使用固定动作、响应上限和超时。云端不可达、宿主代理缺失、真实引擎未就绪或返回合同不完整时，面板显示不可用/部分覆盖，完成百分比不被当成安全结论。

本轮本机已完成 Node 全量回归 238 项（186 通过、52 平台跳过、0 失败）、Linux 最新隔离复验 13 组共 134 项、Windows portable Python scheduler 18/18；生命周期 6/6 来自 Linux、Go `test`/`vet`/build；Windows 无 cgo，未把本地结果冒充 race 验证。v0.6.2 已通过候选 CI 37706748534、预演 37706749722、main CI 37707552435 与正式发布 37708030131；六附件已独立回取验签，并完成玄武生产升级。各环境的具体能力继续以实际代理与引擎就绪状态为准。


### R033 面板账号管理（v0.6.3）

铁幕与玄武 Linux 菜单 14 支持隐藏输入、自定义密码二次确认和随机重置；命令 `sudo tiemu password`、`sudo xuanwu password` 可直接进入。玄武用户中心要求当前密码及新密码确认。固定宿主账号服务只允许更新本角色 admin 凭据，采用 scrypt、原子持久化与管理锁；网页要求会话、同源及 CSRF，更新后旧会话全部失效。root 菜单可恢复忘记的面板密码。

Windows Node 回归 246 项（190 通过、56 平台跳过），隔离 root Linux 账号事务 13/13 通过。真实 Docker/systemd、签名载荷内服务启动、菜单 PTY、可信 TLS 改密与重启保留密码由本版本 CI 验收；正式状态以 v0.6.3 Release 与回取报告为准。

### R034 并发端云状态真实性（v0.6.5）

铁幕冷启动、周期刷新和显式刷新共用当前认证检查；并发状态读取等待检查完成，避免尚未核验时显示默认未配对或旧连接状态。真实 mTLS 回归核验单次上报、并发等待、报告故障与恢复，root 可信身份目录测试进入候选/正式门禁。连接可用仍不代表业务目录、容器、病毒库或检测来源已纳管；v0.6.5 生产验收仍报告这些覆盖缺口。

### R034 玄武网页签名更新（v0.6.6，待正式验收）

玄武设置页显示运行版本、磁盘安装版本、签名发布版本、Git 源码状态与固定任务结果。认证会话、同源检查和 CSRF 校验通过后，仅能请求版本检查或签名更新；root 宿主控制器通过固定 Unix socket 校验进程身份，不向网页暴露命令或 Docker socket。云端任务使用独立服务、锁和安装记录，重用签名、摘要、拒绝降级与安装事务恢复边界。旧版本恢复不要求旧版本不存在的控制器；自更新不会停止正在安装的 worker。Linux 单元、实际服务、签名安装和生产复核须各自通过。
