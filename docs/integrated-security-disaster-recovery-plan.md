# 独立安全项目：需求与开发边界

本报告于 2026-10-04 按用户最新要求修订。铁幕安全和玄武引擎组成独立项目，源代码和后续发布统一放在 Cloud-based-Scanning-and-Removal-Center。APPGOG 仅保留授权、打包、业务备份和迁移，删除安全产品页面与检测接口。

## 必须交付的范围

| 方向 | 要求 | 当前验收入口 |
|---|---|---|
| 业务剥离 | 恢复授权打包界面，保留同机/分机业务功能与数据 | APPGOG 全量业务回归及剩余依赖检查 |
| 铁幕本地 | 独立 Docker、科技盾牌 UI、真实扫描进度、固定主机检查与变化预警 | 独立登录/CSRF/扫描合同、Python 主机检查、Linux 容器安装 |
| 玄武云端 | 独立 Docker、配套面板、一对多节点身份、加密连接、报告状态 | 实际 mTLS、节点互相冒充拒绝、配对/撤销与真实对接 |
| 安装维护 | 各角色一行首装/更新、Linux 中文菜单、支持系统补环境、私有/公开源 | 签名发布验证、同版本重跑、升级身份保留、失败恢复 |
| 查杀处置 | 有范围的病毒扫描、隔离、修复和误报恢复，保留证据 | 真实引擎/特征测试、权限与路径拒绝、恢复及误报演练 |
| 更新平台 | 病毒库、规则、铁幕程序分开版本，签名、兼容、灰度和回退 | 云端发布/本地拉取；未知签名与降级拒绝 |
| 容灾 | 加密异地备份、不可变副本、独立恢复凭据、干净重建 | 恢复实测、围栏与切换演练、实际 RPO/RTO |
| 其他项目 | 配置保护范围，不绑定 APPGOG；后期可嵌入独立面板 | 通用 profile/节点身份与单独认证 |

## 拓扑

两台主机：授权打包同机并装铁幕，玄武独立。三台主机：授权、打包各自安装铁幕，玄武独立。安全系统不负责改变两者业务通信。其他网站也可安装铁幕成为独立节点。

面板首页表现为杀毒产品，部署信息放设置。网页结果必须来自真实接口，缺病毒引擎、基线、权限、代理或连接时展示明确状态。

## 三个失守场景

业务服务失守：最小权限、受保护 profile、固定本机检测和外部证据缩小影响；通用隔离通过预先批准策略实施。宿主 root 失守进入干净重建流程。

云端失联：本地扫描与留证继续，禁止引入无法验签的新内容；不因少量探测失败盲删业务容器。

云端失守：云端不具有 SSH/任意命令权限；停止接受其新内容、撤销身份，独立发布公钥仍约束可运行版本。

## 交付顺序

先完成业务剥离和独立检测/配对/安装，运行真实 Linux 门槛；随后完成通用隔离与修复、规则/病毒库/程序分发、独立灾备和跨主机演练。开发候选、CI 通过、正式签名发布和生产验收分别记录，不能混用。最新完成证据见 capability-status.md 及工作区开发账本。
