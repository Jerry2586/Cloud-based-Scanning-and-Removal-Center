# 铁幕本地宿主发现与文件深度查杀

2026-10-05：R009 宿主发现与文件深度查杀纳入 v0.5.0 安装载荷。正式状态以 v0.5.0 的 GitHub Release、签名验收和六附件回取报告为准；源码检查与 Linux CI 结果分别记录，不能将发布视为生产服务器已经升级。

## 使用顺序

安装后在 Linux 执行 `sudo tiemu` 打开 root 管理菜单。选择 31 发现保护对象，选择 32 重新发现并按序号纳管。选择 33 提交文件深度查杀或继续暂停任务，选择 34 查看保护覆盖与扫描计数。对应固定命令：

~~~sh
sudo tiemu discover
sudo tiemu enroll
sudo tiemu full-scan
sudo tiemu scan-status
~~~

纳管时重新读取候选记录；候选超过 120 秒、目录已变化或 profile 不合法均拒绝。配置切换走管理事务，代理启动与健康检查失败恢复旧配置。发现和纳管不会自动批准镜像、端口、路由或程序签名基线。

浏览器可提交无参数的固定扫描动作。会话、同源/CSRF、Unix socket 身份、并发与冷却检查都必须通过；浏览器不能指定扫描路径、Shell 命令或隔离目标。root 宿主代理检查主机，非 root 网页容器不持有 Docker socket。

## 独立本机一键体检

v0.5.5 首页「一键全面体检」先运行本机环境、软件、服务、端口与容器检查，再执行已纳管目录的文件深度查杀。整项任务保持互斥并持久记录阶段、起止时间和未覆盖原因；页面展示本阶段的实际检查数或文件计数，只有同次环境报告及完整文件队列证据吻合才显示 100%。任务重启中断显示暂停，过期记录不冒充当前扫描。

无需配对玄武。没有引擎、有效病毒库或纳管目录时，环境阶段仍执行，结果明确为未完整覆盖。已有有效本机病毒库时可离线文件查杀；病毒库超过 7 天会拒绝文件扫描，要求先更新。

「杀毒引擎」页面显示实际 ClamAV 版本、官方 daily 库版本/时间/特征数、当前库来源、定时更新与后台任务状态。官方直接来源的「更新官方病毒库」请求固定本机 systemd 服务，经会话、同源、CSRF、角色和来源检查；玄武连接不是前提。已选用玄武签名库时不能混入官方直接库。缺少代理证据显示尚不可核验，不推断为已安装或未安装。

## 发现与环境监测

发现器读取 /opt、/srv、/var/www 下的应用目录候选，读取至多 32 个 Docker 容器的镜像、权限、挂载、进程和可写层变化，以及 TCP/UDP 监听进程。总预算 20 秒，单命令最多 3 秒；不读取容器环境变量，不展示 Token 或密码。

可纳管目录包括经过校验的应用目录、bind/named volume 宿主源，以及支持的 overlay UpperDir /diff。merged 目录、Docker 全存储目录、系统敏感目录和安全软件自身目录不作为通用文件查杀目标。缺少 Docker、ss、存储驱动信息或命令超预算时，显示 partial/unavailable。面板每类最多展示 8 条并保留总数，展示截断不等于检测完成。

镜像、容器配置、可写层与监听变化和上次有效观察比较。首次观察仅说明起点；它不能证明当前环境可信。变化告警也不等于已经识别某个进程或文件为恶意软件。

原有 25 项固定核验继续每 300 秒运行，文件深度任务运行时不并发启动周期核验。覆盖状态结合目录、引擎、独立签名基线、镜像批准、端口配置、纳管数量、报告完整性和时间计算。缺配置、过期、发现风险与不可用分别展示，不能凭容器 healthy 显示整机安全。

## 真实文件队列与进度

深度查杀只扫描 profile 中已纳管的 program_roots/business_roots。队列持久保存在 root 私有目录的 SQLite 文件，使用 DELETE journal 与 FULL 同步；拒绝不受控目录、符号链接、多链接队列及意外 WAL/SHM 文件。

索引上限 200,000 文件、120 秒；不跨文件系统、不跟随符号链接，按设备/inode 去重。单文件上限 64 MiB、解包上限 256 MiB、归档成员上限 10,000、单文件引擎超时 60 秒。这些限制用于控制资源消耗，超限、不可读、特殊文件、目录跳过或引擎无扫描统计都计入未完整覆盖，不能计为 clean。

每个文件经安全路径校验后打开固定描述符，执行摘要与 ClamAV 扫描，并核对扫描前后文件身份、内容状态及路径重新打开后的身份。引擎只加载本产品的官方库；库缺失、元数据不完整或超过 7 天时拒绝深度任务。

面板分别展示 indexed、processed、clean、infected、skipped、errors 与 bytes_scanned。环境核验进度和文件进度独立；indexing 阶段不知道最终总数，不能虚构百分比。finished 仅表示非空索引完整、全部文件处理完成且没有跳过/错误；存在感染仍必须显示告警。partial/failed/paused 都不得显示扫描通过。

目前逐文件启动 clamscan，官方大病毒库重复加载可能明显变慢。此实现优先固定描述符与证据一致性，尚无常驻 clamd 的吞吐能力；扫描持续时间应通过实际目录规模测量，不能给出全机秒级查杀承诺。

## 中断、库变化与处置

队列绑定当前 profile 摘要与病毒库 generation（含 main/daily/可选 bytecode 的元数据和文件身份）。同版本病毒库替换也改变 generation。仅范围与库完全一致时继续已处理队列；不一致重新索引与扫描。每文件前后及最终汇总重新核对库；库中途变化不能发布 finished。

代理重启从队列恢复暂停状态和有界命中证据；损坏证据拒绝复用。旧 profile 的快速报告单独留存，当前配置重新检查。索引中断的任务即便继续处理，也保持清单不完整的 partial 状态。恢复代表之前文件的扫描记录保留，已处理文件之后仍可能改变；下一次新扫描重新读取文件。

命中证据最多保存 32 条，面板只展示清洗后的有界记录。达到展示或证据上限仍保留真实感染计数。隔离必须由 root 菜单明确选择证据并重新复扫；配置、数据库、凭据、系统目录、共享可写文件及多链接文件只告警。隔离不结束已运行进程，也不恢复数据库或重建被攻破的宿主。

## 当前覆盖边界与验证

本轮可检查纳管目录文件、宿主固定配置、容器元数据/进程/可写层变化与监听；没有完成内存/内核恶意代码检测、全部镜像 lower layers 扫描、实时 EDR 自动封控、Cloudflare 自动修复或业务异地故障切换。宿主 root 失守仍需要独立证据和干净主机重建。

本地 Windows 测试只证明可运行的合同/接口/发现解析及静态检查。Linux CI 单独验证 root 文件队列故障与恢复、Unix socket、真实 ClamAV 特征库扫描，以及 Docker/systemd 安装升级。真实引擎的隔离测试特征库不冒充官方病毒库公网更新；官方库历史验收另见能力矩阵。用户生产服务器、arm64、RPM 软件源和跨主机规模仍需单独验收。
