# 域名与自动 HTTPS

铁幕和玄武独立拥有面板域名及证书。首次安装识别公网 IPv4；用户将域名解析到服务器后，在面板「设置 → 访问域名」填写域名并保存，或运行 `sudo tiemu` / `sudo xuanwu` 的菜单 35。菜单 36 查看真实任务状态。已自行完成 DNS 解析时不要求 Cloudflare Token。

## 操作与结果

只填写域名，例如 `tiemu.example.com`，不用填写协议、端口或路径。保存后显示「正在验证并申请证书」；只有证书链、域名、有效期、密钥和正确角色的 HTTPS 健康检查全部通过，才显示实际地址。失败时显示原因，保留原 IP 入口或之前已启用的域名。申请成功后每日定时检查续期；更新程序仍保留身份、IP 回退和域名配置。

HTTP-01 使用公网 80 验证路径，域名访问使用 443。DNS 必须使公网请求到达本机验证路径；防火墙、Cloudflare 回源规则、强制跳转或其他网站拦截该路径时，任务会明确失败。程序实际请求随机挑战并核对内容，不把解析成功当作证书已申请。Cloudflare 代理可用性以此真实路径检查为准。

## 两角色的访问边界

铁幕原 IP 面板端口为 8790；玄武浏览器管理入口为 8791。玄武 9443 继续使用双向证书和节点令牌，不改成浏览器公开接口。程序和两角色各自的服务、Unix 控制 socket、证书代次、状态与审计按角色隔离。首次纯 IP 安装不占用 443，域名申请成功后才启用自己的入口。

## 独立入口与端口冲突

两端域名配置只操作各自的证书、配置与 systemd 服务。程序不读取或改写 APPGOG、Nginx、Caddy 或其他业务项目配置，不重启其他项目容器，也不要求它们升级。安全域名任务使用独立锁，避免两个安全角色争用入口。

自动 HTTP-01 验证需要本机公网 80 可用；标准 HTTPS 入口需要 443 可用或已由当前安全角色自己的入口持有。端口被其他服务占用时，申请停止，面板和 Linux 菜单显示具体端口，保留原 IP 或已启用的域名。程序不会抢占端口。已有网站使用 80/443 的机器，需要独立公网入口或另外明确配置的接入方式；仅修改 DNS 不足以解决监听冲突。当前版本不提供自动改写第三方代理的功能。

旧开发版遗留的外部入口恢复记录保留并报告待检查，程序不会用它继续改写其他项目。已发布的 v0.5.5 不含该适配器，v0.5.6 正式发布已取消；标签历史保留。

## 验证范围

Node 回归覆盖登录、CSRF、Origin、Host、状态和证书轮换。Linux Python 回归覆盖任务事务、DNS/HTTP 限制、恢复和安装互锁。回归覆盖端口冲突时无外部服务操作、旧外部事务保留与两角色入口互斥；systemd 验收覆盖控制 socket、TLS 转发及签名程序升级后的入口状态。夹具证书用于验证信任与路由，不代表已在生产域名签发 ACME 证书。正式运行状态以对应 CI 和部署后的真实健康检查为准。
