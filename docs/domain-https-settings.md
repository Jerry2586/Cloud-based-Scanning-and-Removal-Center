# 域名与自动 HTTPS

铁幕和玄武独立拥有面板域名及证书。首次安装识别公网 IPv4；用户将域名解析到服务器后，在面板「设置 → 访问域名」填写域名并保存，或运行 `sudo tiemu` / `sudo xuanwu` 的菜单 35。菜单 36 查看真实任务状态。已自行完成 DNS 解析时不要求 Cloudflare Token。

## 操作与结果

只填写域名，例如 `tiemu.example.com`，不用填写协议、端口或路径。保存后显示「正在验证并申请证书」；只有证书链、域名、有效期、密钥和正确角色的 HTTPS 健康检查全部通过，才显示实际地址。失败时显示原因，保留原 IP 入口或之前已启用的域名。申请成功后每日定时检查续期；更新程序仍保留身份、IP 回退和域名配置。

HTTP-01 使用公网 80 验证路径，域名访问使用 443。DNS 必须使公网请求到达本机验证路径；防火墙、Cloudflare 回源规则、强制跳转或其他网站拦截该路径时，任务会明确失败。程序实际请求随机挑战并核对内容，不把解析成功当作证书已申请。Cloudflare 代理可用性以此真实路径检查为准。

## 两角色的访问边界

铁幕原 IP 面板端口为 8790；玄武浏览器管理入口为 8791。玄武 9443 继续使用双向证书和节点令牌，不改成浏览器公开接口。程序和两角色各自的服务、Unix 控制 socket、证书代次、状态与审计按角色隔离。首次纯 IP 安装不占用 443，域名申请成功后才启用自己的入口。

## 同机 APPGOG

升级到支持 `com.appgog.shared-ingress=v1` 的 APPGOG 后，可共享其 80/443。适配器只写入 root 控制的安全角色站点目录，经 Caddy 配置验证后启用，验证加密上游并检查正确角色响应。安全域名不能与授权、打包域名相同。入口改动及证书续期需要短暂重启 APPGOG 业务容器；页面显示这一影响。入口操作与 APPGOG 安装、更新、迁移采用同一互斥锁。

旧 APPGOG 或未知代理占用 80/443 时，任务提示先更新或检查入口，不改写未知服务的配置。独立服务器使用自己的 HTTP 验证服务和 443 TLS 转发；私钥只保存在 root 管理目录。同机两个安全角色需要各自有能路由到对应角色的共享入口。

## 验证范围

Node 回归覆盖登录、CSRF、Origin、Host、状态和证书轮换。Linux Python 回归覆盖任务事务、DNS/HTTP 限制、恢复和安装互锁。Docker 验收覆盖真实 Caddy 挑战路径、两角色 HTTPS 转发、错误上游证书拒绝和配置恢复；systemd 验收覆盖控制 socket、TLS 转发及签名程序升级后的入口状态。夹具证书用于验证信任与路由，不代表已在生产域名签发 ACME 证书。正式运行状态以对应 CI 和部署后的真实健康检查为准。
