# 安装环境修复与本机验收

本轮仅修复铁幕安全/玄武引擎的独立安装入口与环境准备，不修改 APPGOG 业务项目。

## 根因

- `scripts/install-independent.sh` 是源码内部路径。未获取源码、停留在服务器家目录时该文件不存在。
- 原环境检查遗漏 Bash、gzip、find、CA 包、Python 实际能力等依赖。
- 原逻辑遇到“存在但过旧”的 Compose 直接退出，未升级。
- 原 RPM 病毒引擎只调用 dnf，与安装器声明的 yum 支持不一致。
- 私有仓库匿名下载不可用，首次认证缺少引导。

## 修复行为

- 根目录 `install.sh` 是独立 POSIX 引导器，可用绝对路径从任何目录运行；只需先可信获取这一个文件，不需要 Git 或完整源码。
- 下载并校验签名正式 RUN 后调用角色安装器。引导器修复 Bash、归档、HTTPS/CA、GNU 工具和 OpenSSL 能力。
- 私有发布源支持隐藏输入令牌、root 私有存储、显式 `--token-file`；拒绝不安全权限/所有者和符号链接，认证下载仍独立验签。
- 新环境模块补齐宿主检查依赖，检测 Python >=3.9、sqlite3/ssl、OpenSSL Ed25519 与证书扩展能力。
- 安装/升级 Compose 至 >=2.24.0，缺失 Buildx 自动补装；发行版 docker.io 使用原渠道插件，避免替换业务容器运行时。
- 检测 Docker context、systemd 服务与守护进程；错误给出原因，禁止连接远程 Docker 或删除冲突运行时。
- ClamAV 安装沿用 apt/dnf/yum；病毒库不可用仍显示未就绪。
- README 已把正式单文件入口与源码内部入口分开。

## 验收范围

- 环境决策测试共 27 项：26 通过，1 项因 Windows Git Bash 未创建真实 POSIX 符号链接而跳过。Linux CI 中该用例必须执行；跳过不记为通过。测试不安装真实软件、不更改系统源或容器。
- shell 语法检查覆盖源码 scripts/tests 与独立引导器；通过。实际 OpenSSL Ed25519 签名/验签与证书扩展能力探测通过。
- 发布打包器显式要求新的环境模块存在，避免漏文件后才在安装过程中失败。
- Node 74 项：使用 Git 附带 GNU tar 后，68 通过，6 个 Linux 专属项跳过；未修改发布验证器来适配 Windows。
- Python 8 个测试模块共 69 项：18 通过，49 跳过，2 个错误。两处错误均来自 host-agent.test.py 使用 Windows 缺少的 os.O_DIRECTORY；原 HEAD 副本复现相同错误。不能据此宣称 Python 完整回归通过，Linux 路径待实机/CI 执行。
- Windows 本机没有 Docker、WSL 或 systemd，真实 Linux 首装、系统包安装和已有业务主机升级尚未在本轮执行。新增用例已加入 Verify/Release 工作流；上述数字为本地验收结果，后续 Linux CI 结果以对应提交的 Actions 运行记录为准。
- 本轮未发布新版本。包版本仍为 0.4.0；部署修改需要新的签名正式版本，禁止用同版本内容覆盖旧安装。

## 使用边界

无法承诺所有 Linux 环境都自动成功：需要受维护系统、root/systemd、支持的 CPU、可用软件源、磁盘空间和 HTTPS 网络。私有仓库的首次引导文件需要可信获取，不能伪造匿名公网一键地址。现有事务回滚保护角色程序/身份/配置；已安装的系统依赖与软件源不属于程序回滚范围。
