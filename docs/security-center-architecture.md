# 铁幕安全 / 玄武引擎：独立架构

更新日期：2026-10-08。本文是当前拆分后的架构合同；实际验收见 capability-status.md。历史 APPGOG 内嵌安全实现已迁出，业务系统与安全系统分别发布。

## 项目与权限

| 组件 | 部署与责任 | 权限边界 |
|---|---|---|
| APPGOG | 授权、打包及业务数据；同机或分机部署 | 不加载安全产品页面、检测路由或扫描服务生命周期 |
| 铁幕网页容器 | 独立登录、固定扫描请求、报告和玄武连接 | 非 root、只读根文件系统；无 Docker socket、无任意命令接口 |
| 铁幕宿主代理 | systemd 服务；按 root 管理的 profile 只读检查主机 | 固定 Unix socket 动作与资源预算；不接受网页路径、命令或处置策略 |
| 铁幕 Go 检测主控（v0.5.10 正式基线） | 宿主代理调用；调度 ClamAV、Trivy、Osquery、Falco | 固定可执行文件、固定输入来源、双并发及期限；分类证据不授予处置权限 |
| 玄武容器 | 独立 mTLS、节点身份、状态核对、策略与认证管理面板 | 不登录节点、不执行命令、不持有业务 Docker socket 或发布签名私钥 |
| 发布环境 | 签名发布包；保管离线验签链 | 与业务机、玄武管理域分离 |

安全项目的 local/cloud 是两个独立安装角色，各自一个容器。铁幕另有宿主 systemd 代理，这是只读容器不能检查整机环境所需的边界。安全网页不挂载整机根目录。

两机拓扑：业务同机运行授权与打包，铁幕保护该主机；玄武独立。三机拓扑：授权机与打包机各装自己的铁幕，玄武独立。节点命名和身份与具体业务无关，可扩展到其他网站；首页不展示部署拓扑。

## 数据流与身份

本地网页经 Unix socket 请求固定检查。检查返回真实进度、25 项固定核验结果、覆盖信息和变化记录。铁幕用私有 CA 客户端证书、每节点独立令牌以及固定云端地址建立 mTLS，主动上报并查询自己节点的状态。玄武 reader 只提供管理员读权限，不交付到铁幕主机。

配对使用有认证加密的 .icpair 包，导入时核对独立渠道提供的 CA 指纹、证书用途、期限、节点名称、私钥匹配和真实握手；成功后再切换身份。错误身份不覆盖现有连接。玄武可登记多个节点，撤销一个节点后其旧身份失效。端口可连接只证明 TCP 可达，不证明已认证。

## 检测与可信基线

程序和配置摘要依赖本机独立签名基线。基线格式 ironcurtain-baseline/v1；路径、签名及公钥由本机 profile 指定，保护目录需完全匹配。未知文件、配置变化、权限异常、镜像变化分别留证。不得从受疑主机直接生成并批准新基线。

宿主发现与目录纳管由 root Linux 菜单执行；纳管不会批准签名基线或镜像。新增文件队列只覆盖已纳管目录，实际文件进度、跳过/失败与中断恢复独立展示，详见 [本地宿主发现与文件深度查杀](local-host-full-scan.md)。

ClamAV 是可选真实引擎，未安装或库过期显示不可用。Cloudflare 模块仅 GET 采集并比对明确批准的配置基线，不修改账号设置。端口允许名单由管理员定义；新端口提示风险，不自动关掉 SSH。

没有基线、扫描超预算、目录无法读取、代理失联、历史损坏或检查缺失时保持未知/不可用。检查百分比计算完成的检查项，不虚构已扫描文件数量；全部完成也不等于全部通过。

R023 在现有主机检查之外增加 Go 四引擎联合检测任务。任务结束进度与有效覆盖分别计算；缺少引擎、漏洞库或探针健康证据时保持未就绪/部分覆盖。网页不能指定路径、镜像或命令；Trivy 只读取本机不可变镜像，Osquery 只执行固定资产查询，Falco 只读取可信事件文件。具体就绪条件、权限与本批验收边界见 [Go 检测主控](go-manager.md)。R023 已纳入 v0.5.10；真实四引擎实机覆盖仍须分别验收。

R024 在设置页和 Linux 菜单增加只读四引擎就绪检查：认证网页 → 固定 /engines Unix 动作 → 固定 Go --readiness 与原 ClamAV 状态；不提供安装任意软件或执行自定义命令的入口。报告有缓存期限、单在途任务及维护互锁，过期/无法验证的依赖保持不可用。Trivy 固定漏洞缓存的可信路径、元数据与有效期成为扫描准入条件；其本地新鲜度策略不等于数据库发布者认证，尚未固定数据库 generation。详见 Go 检测主控文档。R024 已纳入 v0.5.10；依赖未安装不会被显示为可用。

## 更新与恢复

v0.6.6 为玄武增加独立宿主更新控制器。非 root 面板经固定 Unix socket 读取状态、请求版本检查或签名更新；准确校验进程身份，动作由 root 管理的固定 systemd 服务执行。云端角色使用自己的回执、任务目录和锁，不接触铁幕扫描 socket，也不向容器挂载 Docker socket。控制器、定时器和 worker 纳入安装/管理服务快照，正在自更新的 worker 在升级及恢复期间保持执行。

固定引导器验签后执行角色安装。安装记录、载荷摘要、同版本一致性、拒绝降级、服务健康和事务恢复共同约束升级。管理操作也有 root 私有配置快照；配对/撤销/配置变更失败会保留恢复记录并重建服务，直到健康检查通过。

安装和配置恢复快照包含私密配置，位于 root 专属目录，不等于异地加密灾备。通用恶意文件命中会对打开的文件描述符重新扫描并生成有界证据。root Linux 菜单按完整证据 ID 显式隔离/恢复，先复制、校验和落盘再移除原文件；仅允许 root 管理的单链接业务文件，配置、凭据、数据库、系统和安全程序目录、共享可写文件禁止自动处置。恢复不覆盖目标，恢复为 root:0600 并保留隔离副本；隔离不结束已运行进程。网页只显示记录，不能发起处置。Linux 新功能验收见能力表；独立不可变备份和自动故障切换仍需实现与演练。

签名哈希规则仅承载摘要、标签、序号、兼容版本及有效期，不承载路径、命令、基线或处置指令。发布私钥留在独立发布环境，玄武导入经验签的数据，铁幕以节点身份主动拉取。激活独立保留签名高水位，以进程锁避免并发覆盖；同机恢复保留当前规则与高水位，不能恢复旧包来绕过撤销或降级限制。规则更新和规则状态见 [签名规则说明](signed-rules.md)。

同机同版本加密恢复已经过真实 Linux 容器验收，归档先认证再解密，恢复保留现行身份、CA 和撤销记录。异地不可变副本、干净主机重建、跨版本迁移仍须独立验收。

云端失联时保留本地固定周期检查，不接受未验签更新。云端失守时可以解绑及撤销身份；拒绝任何云端任意命令能力。宿主 root 失守会影响同机代理可信度，需独立证据和干净主机重建。

## 验收要求

独立登录、会话/CSRF、固定参数、并发与频率限制、缺依赖、篡改签名及 mTLS 正反例须通过接口测试。Linux CI 要运行真实 Docker/systemd 首装、同版本重跑、更高版本升级、身份保留和配对扫描。事务故障测试使用真实 Linux 文件系统，但服务替身不能冒充真实部署。两机/三机跨主机、apt/dnf 和 arm64 扩展验收应单独记录。

## R031 周期任务与维护边界

v0.6.2 将周期检查放在铁幕宿主代理内执行。任务类型是固定枚举，分别覆盖快速环境体检、已纳管文件查杀和本地联合检测；面板只配置开关与受限时间间隔。任务记录使用严格版本合同，包含任务 ID、尝试次数、阶段时间、结果状态和下一次计划时间，状态文件原子替换并限制在 root 私有目录。

所有检测启动、病毒库更新、规则维护和节点管理共用管理租约。检测不接受来自浏览器的任意命令、文件路径、镜像名或网络目标；维护期间任务只会延期，运行中的配置不会被覆盖。代理关闭时保存中断状态，重新启动后显示中断/延期并重新安排，避免瞬间显示百分之百或伪造完成。

本地界面把“完成进度”与“有效覆盖、引擎就绪和安全结论”分开显示。没有本机代理、没有可信基线、真实引擎未就绪、云端失联或返回数据无法通过合同校验时，结果保持不可用或部分覆盖。玄武只接收经过身份认证的摘要、状态和策略结果；它不远程执行主机命令，也不替代铁幕本地检查。
